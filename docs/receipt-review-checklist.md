# Receipt review: implementation and acceptance checklist

This checklist tracks all 71 numbered sections in the supplied **TripTab — End-to-End Receipt Scanning, ChatGPT Integration, Itemisation Integrity & Review Hardening** review. The initial recheck used source commit `a84f9f04fafcaf7cef8f6c56324a5d0f209465eb`. It found that successful API receipt upload and quantity extraction did **not** complete the wider review. In particular, a conversation message mentioning the printed total was not durable scan evidence or a server-enforced reconciliation boundary.

The user has confirmed that the public site's shared-API upload produced receipt items. That confirms that individual API journey, not the hosted ChatGPT-plugin journey or general vision accuracy. No paid model requests are made by deterministic verification.

Status meanings:

- **Present**: implemented in the rechecked source; this does not imply hosted acceptance.
- **Required**: mandatory product or verification work still missing or partial at the recheck baseline.
- **Hosted gate**: needs an actual authorized hosted client/session; local fixtures cannot establish it.
- **Deferred**: explicitly optional or separately deliverable in the supplied review; the core safeguards still apply.
- **Plan**: sequencing or a summary of requirements, rather than a separate implementation.

The third column records the earlier baseline, so an entry marked Required there describes the gap found before this work. The fourth column records the current source recheck. Implementation evidence is separate from the final test/build/mobile release result and from actual hosted/client or paid visual-model acceptance. The [receipt release runbook](receipt-release-runbook.md) records those separate gates.

## Deliberate separate scope

The review explicitly permits **ordered multi-photo receipts** and **first-class signed/item-specific financial adjustments** to follow in a separate PR. The core release still must retain unsupported adjustment text, warn, and prevent silently applying an incorrect global discount. Compact sticky scan status, calibrated blank-image detection and a separate processing-attempt identifier are suggestions, not reasons to defer the required integrity work.

## Hosted acceptance record

No actual fresh hosted ChatGPT or Codex session, plugin version/tool availability verification, or paid visual-model evaluation is recorded by this recheck. Do not interpret an owner-confirmed API upload, local `/mcp` fixtures, synthetic model responses, browser mocks or a successful Site deployment as those checks. Record the exact client, release, tools and result following the linked runbook before claiming that path production-ready.
